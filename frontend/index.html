    There’s a reason for every route.
    One shared state carries the complaint through each decision. Open a step to see what it does.
    
      
    
        
    Context stays.
    Decisions move forward.
    A missing detail pauses the workflow. A customer’s answer continues it from validation, with the earlier context intact.
    Explore the API 
    
        
    
          
    01Check privacy first+
    Scan for supported sensitive-data patterns and create a redacted copy. Flagged complaints go straight to a compliance ticket before extraction.
    compliance → extract or compliance_escalation
    
          
    02Extract the useful details+
    Convert the email into a Pydantic model: customer, account, amounts, and issue. Versioned prompts and deterministic fallback keep the demo usable without an API key.
    email → ExtractedInformation
    
          
    03Ask for what’s missing+
    Missing details produce a clarification question. The next answer is merged into the saved state, then checked again. Three attempts are allowed.
    validate → clarify → validate
    
          
    04Verify against the record+
    Check the account, customer name, claimed amount, expected amount, account status, and discrepancy against mock billing records. Failed checks include reason codes.
    verify → reason_codes
    
          
    05Choose the next step+
    Verified requests get a drafted response. Mismatches get a billing ticket. The outcome, execution history, and ticket are saved in SQLite.
    respond or billing_review → SQLite
